# AdvisePoint Docs v1.3.0 candidate 12 verification

Date: September 22, 2026. Local-test candidate only.

## Change and cause

The candidate-10 fast-original route treated every selection over 50 pages
the same, including a partial native-PDF range. Its instructions required
selecting the range again in the reader, but the file delivered was the whole
original. Native ranges now use the existing selected-page copying worker
regardless of the 50-page threshold. No image-rendering pass is added.

Large whole-native-document requests still hand off the unchanged original.
Rendered-PDF large-job handoff remains unchanged. Protected native PDFs that
cannot safely be copied retain their security and explicit instructions to
choose the range in the original reader. Print-denied files remain refused
by the preparation flow.

## Automated results

- Handoff/download/attachment suite: 15 passed. New Chromium and Firefox
  tests exercise the library viewer's Range controls for 1-, 50- and 51-page
  native subsets. Each output page's text and order are checked, as are the
  exact page count and primary reader button's subset-blob URL. No raster
  sheets/canvases are allocated. Original bytes remain unchanged.
- Large native-print suite: 7 passed. A 101-page subset contains original
  pages 10–110 with all page dimensions and rotations preserved; first,
  middle and last page text match. Whole-document handoff, three supplied
  manuals, protected-PDF behavior, timeout, cancellation/retry, warning and
  actual Chromium PDF-reader opening also pass.
- Print-dialog/local-candidate suites: 12 passed on final rerun. Includes
  candidate-11 number editing, both browsers, both PDF modes, Done/Close/Escape,
  active-transfer cleanup, test-library isolation and disabled updates.
- Production dependency audit: zero reported vulnerabilities.
- Typecheck output matches candidate 11 exactly; 14 pre-existing diagnostics
  remain. This is not a clean TypeScript check.

Total: 34 focused checks passed. This is not a rerun of the entire candidate-10
347-test campaign. Two earlier rendered-dialog attempts hit the sandbox's
temporary-disk-space safety limit. Disposable test/build copies were removed;
the guard was not weakened and the final full suite passed.

## Package verification

Delivery gates check archive integrity, candidate/version markers, native
x64/ARM64 PE architecture, identical shared application bundles, source
identity, local-test launchers and unchanged v1.2.8 runtime/updater bytes.
The source archive is also independently extracted and rebuilt in local-test
mode for a distribution comparison. Detailed results accompany the project
verification evidence.

No GitHub publication, updater enablement or library reset is performed.
Existing original files, metadata and rendered pages are preserved.

## Windows acceptance

Linux Chromium/Firefox automation is not Windows Chrome/Edge/Firefox or
physical-printer certification. On each laptop, test a native manual with
100–110 and 300–350. Its reader should contain 11 and 51 pages respectively;
choose All pages in the prepared subset. Test All pages separately for a full
manual. Protected-original fallback explicitly requires selecting the original
range in the reader.
