# AdvisePoint Docs v1.3.0 candidate build

Historical candidate instructions. Final production packages are described in
`v1.3.0-final-build.md`; do not use the local-test flag for a final rebuild.

This is a local-test integration of PDF Prototype 0.4 into the v1.2.8 source baseline. It is not a published release or an update package. Existing library data must not be removed or converted automatically.

Candidate 13 adds permission-aware temporary print-image subsets for protected
native PDFs whose encrypted pages cannot be copied by pdf-lib. PDF.js checks
printing permission first; high-quality output is 200 DPI, low-quality-only
output is 150 DPI. One canvas at a time, 8-million-pixel per-page budget,
128 MiB image/output budget, timeout and cancel/retry bound the operation.
Stored original bytes remain unchanged. Done revokes temporary blobs.
Actual 100–103 ranges from all three supplied native manuals are tested in
Chromium and Firefox for four pages and corresponding visible content.

Candidate 12 routes all native PDF subsets through existing PDF-copy preparation,
including selections above 50 pages. Whole-native-document jobs over 50 pages
keep direct handoff. Rendered-PDF routing is unchanged; candidate 13 supersedes
the protected-original fallback. Chromium/Firefox tests inspect every page in 1/50/51-page subsets;
the large-print suite checks 101-page content, dimensions and rotation.

Candidate 11 fixes print-range editing, preserves empty drafts, selects full
values on click/focus, and prevents viewer shortcuts or background page changes
from interfering. The Chromium/Firefox dialog suite exercises real keyboard
entry in both retained and rendered PDF viewers, not only programmatic fill.

Candidate 10 adds original-PDF handoff for selections over 50 pages and an
availability-gated original-download icon in the extracted-text toolbar.
`pdf_rendered` is an additive default-zero database field: a retained original
on a rendered import must not switch the page viewer to native PDF mode.
Existing image-only entries are not automatically changed; exact-file attachment
publishes verified bytes before updating only retention metadata. New fallback
imports retain their original. No automatic data deletion or conversion occurs.
Packaged `CANDIDATE` contains `13`; version remains 1.3.0.

Run `scripts/pdf-handoff.test.mjs` with `APD_RENDER_FIXTURE` and
`APD_RESTRICTED_MANUAL` for threshold, availability, byte/filename fidelity,
Chromium/Firefox controls, attachment and safety regression checks.

Candidate 9's preserved behavior isolates rendered-print preparation in a child process, validates the
PDF before waiting for clean natural exit, and adds bounded native-stderr,
phase/memory/exit diagnostics. Cancellation and failure wait for confirmed exit
before cleanup. Active preparation holds off idle shutdown. Candidate 8's
guarded pixel-conversion optimization and candidate 7's in-app dialog/Done
behavior remain.
Chrome, Edge and Firefox on Windows x64/ARM64 require candidate-13 acceptance.

`scripts/rendered-print.test.mjs` now exercises process kill, post-completion
failure, stalled teardown, near-completion cancellation, parent loss, and two
full 724-page preparations. Fault-injection tests temporarily replace the
worker in their disposable build and restore it; do not run concurrent tests
against that dist directory. No runtime test override is shipped.

The new `server/workers/print-pixels.cjs` helper must ship beside `rendered-print-worker.cjs`; the existing worker-directory copy includes it. Run `node --test scripts/rendered-print-pixels.test.cjs` for compatibility, channel-order, transparency, alignment, remainder and fallback coverage. With the exact disposable 7353 fixture, `APD_EXPECTED_PRINT_SHA256=0af93fd4b218c85ccedea80a52ac827657beb33f92f8e95d8293a3cbfdc55f02` makes the rendered-print suite enforce byte-identical output.

New QA: `APD_RENDER_FIXTURE=/path/to/disposable-724-page-fixture node --test scripts/print-dialog.test.mjs` requires Playwright Chromium and Firefox. Use `APD_PRINT_EMBEDDED=1` with `scripts/large-pdf-print.test.mjs` to check the retained dialog path. PC-copy ownership/deferred cleanup tests are in `scripts/pdf-open.test.mjs`. No Windows library is needed or opened by these tests.

## Rebuild the shared application

Use Node.js 20 or newer and the committed lockfile. From the source root:

```sh
npm ci
VITE_APD_LOCAL_TEST=1 npm run build:nobump
```

The environment assignment above is for a Unix shell. In Windows PowerShell, use `$env:VITE_APD_LOCAL_TEST="1"` before `npm run build:nobump`. The build writes `dist/build-mode.json`; local-test packaging refuses a normal-mode build.

The source's ordinary production launchers and updater are retained for later release engineering. Do not use them for this candidate. Only the packaged local-test launcher isolates the library and port.

## Package Windows candidates

The package builder requires the verified v1.2.8 architecture ZIPs and their matching native runtime modules. It does not cross-compile native modules. The baseline Node runtime is 20.18.1.

```sh
node scripts/package-windows.mjs --baseline /path/to/AdvisePoint-Docs-v1.2.8-x64.zip --output /path/to/AdvisePoint-Docs-v1.3.0-x64.zip --arch x64 --x64-modules "/path/to/x64/AdvisePoint Docs/node_modules" --local-test 1
node scripts/package-windows.mjs --baseline /path/to/AdvisePoint-Docs-v1.2.8-arm64.zip --output /path/to/AdvisePoint-Docs-v1.3.0-arm64.zip --arch arm64 --arm64-node "/path/to/arm64/AdvisePoint Docs/node/node.exe" --arm64-modules "/path/to/arm64/AdvisePoint Docs/node_modules" --local-test 1
node scripts/package-source.mjs --output /path/to/AdvisePoint-Docs-v1.3.0-source.zip
```

Run architecture packaging sequentially because both runs regenerate the bundled Welcome Guide. Verify ZIP integrity, native PE architecture, source-to-bundle hashes, updated Welcome Guide, updater identity and local-test markers before distribution.

## Local-test behavior

The packaged Start BAT runs `local-test.cjs`, port 5101, and `%LOCALAPPDATA%\AdvisePoint Docs v1.3.0 Test\AdvisePoint Docs`. The normal packaged server entry also passes through this wrapper. Port 5000 and the working library are not used. Update UI, requests and API actions are disabled; update/shortcut BAT entry points display a disabled message. Do not invoke internal server or updater files directly.

`Reset library (backup first).bat` is a separate, explicit utility. Keep it with `reset-library.cjs`, `node` and `node_modules`. It asks which library to reset and requires a typed confirmation. It verifies a consistent SQLite snapshot and copied files, preserves the original folder, then creates an empty active folder. It is never run by the application.

## Verification commands

Use a normal-mode build for existing viewer/upload/update-panel regression tests, since those explicitly test the production update controls. Use a local-test build for candidate isolation and retained-PDF integration tests. Playwright Chromium must be installed for browser tests.

```sh
node --import tsx --test --test-concurrency=1 scripts/pdf-viewer.test.mjs scripts/upload-page.test.mjs scripts/update-panel.test.mjs
node --test scripts/reset-library.test.cjs
node --import tsx --test --test-concurrency=1 scripts/pdf-integration.test.mjs scripts/local-candidate.test.mjs
```

Set `APD_MANUALS` to a folder containing the three supplied Kyocera manuals for the real-manual integration checks. Tests use disposable libraries, never the working Windows library. Linux tests do not replace native Windows x64/ARM64 field testing, external-reader associations or physical printing.

to the disposable fixture folder produced by the full responsiveness test.

Chromium preparation controls. It requires qpdf and Playwright Chromium.
