# v1.3.0 candidate 5 verification

September 21, 2026. Local testing only; no GitHub publication or enabled update path. Existing user libraries were not opened, reset or deleted.

## Scope and implementation

The viewer now directs image-based documents to sequential print preparation, preserving the retained-PDF route. A separate worker decodes one saved page at a time and embeds its RGB pixels with lossless compression in a streamed PDF. It does not construct hundreds of browser image elements or treat image errors as successful completion.

The server checks every selected stored page, confines image paths, validates dimensions and confirms the expected completion count, file length and final trailer before exposing the PDF. One worker runs at a time. Cancelling waits for worker termination before admitting a retry. Corrupt/missing pages and budget/time failures never expose partial output.

The UI has explicit ready/open/download/PC-reader actions and cancel/retry. Same-origin headers guard start/cancel/native-open actions. File delivery supports range requests. Temporary output is separate from library data, bounded to 1 GiB across in-process jobs, with 30-minute inactivity expiry. Known orphan files older than 24 hours are cleaned at startup without following links or recursing through unknown files. There is a ten-minute overall deadline and 60-second per-page deadline.

The result is an image PDF, not the original searchable PDF. Existing saved pixels are not recompressed lossily. Current page size uses 240 DPI; older 110/200-DPI libraries need Fit to paper and a margin/orientation check.

An initial 512 MiB cap failed safely at page 600. No partial file was offered. The final 1 GiB budget completed the entire manual. The full test uses copies of a disposable library, never a user's working library.
