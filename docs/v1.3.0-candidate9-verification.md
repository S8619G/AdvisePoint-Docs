September 22, 2026. Local-test x64/ARM64 packages with shared source.
No GitHub publication, update enablement or library reset.

## Changes

Rendered-print preparation now uses a dedicated child process launched with
the current packaged Node executable. The library server no longer shares
the preparation worker's native rendering process. Normal completion flushes
IPC, disconnects and exits naturally. The parent validates completion and
waits for clean exit before renaming/exposing the PDF.

Cancellation, failure and deadlines terminate only the preparation process.
Cleanup and admission of another job wait for confirmed process close. If
termination cannot be confirmed, the busy slot and files remain protected.
An active print job also holds off idle shutdown, including a pending stop.
The existing 60-second per-page and ten-minute total limits remain, with a
five-second exit deadline after completed-file validation.

The rotated upload journal now records job/PID, progress, memory samples,
finalization stages, exit code/signal and up to 8 KiB of native stderr input
per job with path redaction. Later startup marks unfinished candidate-9 jobs.
Logging does not contain PDF page pixels or document text.

Candidate 8's guarded pixel optimization, full resolution, lossless output,
print-dialog controls, retained-PDF behavior, isolated test storage and
disabled updater are preserved. The original ARM64 failure's precise cause
is still unconfirmed. Process containment does not guarantee protection from
system-wide resource exhaustion or every Windows-specific failure.

seconds in the final sandbox run. Journal completion times were 99.659 and
100.135 seconds; polling accounts for the small difference. Both exited
cleanly and produced exactly 673,101,792 bytes with SHA-256:

`0af93fd4b218c85ccedea80a52ac827657beb33f92f8e95d8293a3cbfdc55f02`

This matches the prior verified candidate-7/8 output byte-for-byte. The first
job also passed qpdf structural validation, 724-page count, exact RGB samples

were 1.60 to 3.05 milliseconds. The largest sampled child RSS was 586,493,952

These runs were slower than candidate 8's earlier 68.7-second sandbox run.
This was not a controlled performance comparison and no additional speedup
is claimed. Candidate 9 prioritizes containment and recovery; actual timings
and stability must be checked on both Windows laptops.
