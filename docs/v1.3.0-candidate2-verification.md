# AdvisePoint Docs v1.3.0 candidate 2 verification

Prepared September 20, 2026. Local-test delivery only: separate port 5101 and existing isolated v1.3.0 test library, updates disabled, no GitHub publication, no production library access or automatic reset.

## Functional changes

- Copy-restricted PDFs that permit full-quality printing offer an explicit rendered-page import with authorization, time and storage warning, plus skip/cancel controls. No automatic conversion occurs.
- Confirmed fallback uses the same normalized text extraction as v1.2.8 and its legacy WebP page renderer/viewer. Search is indexed before background rendering; the original PDF is not retained in this mode. Existing retained-PDF and image-based documents are unchanged.
- Per-upload journal records correlation IDs, filename basenames, bytes, stages, errors/status, document IDs and elapsed time. It excludes content, metadata and secrets, survives restarts, rotates through three 2 MiB files and identifies unfinished requests/render jobs without replaying them.
- Normal candidate startup captures stdout/stderr in two bounded 10 MiB logs. Normal diagnostics includes current/recent upload and console logs. An unwritable journal does not fail a successful import and emits a warning.

## Build and security gates

The v1.2.8 updater and runtime module bytes remain unchanged. One architecture-neutral source ZIP accompanies both packages.

The dependency audit reports zero npm findings. The full TypeScript check still reports the same 14 pre-existing diagnostics in LibraryScanPanel, backup-scheduler and locate; no new diagnostics were introduced. The bundled Node runtime remains 20.18.1; an npm audit is not a complete runtime security certification.

## Remaining acceptance

Windows ARM64/x64 execution, browser-specific behavior and physical printing require laptop testing. The initial five-file report is not conclusively explained in its entirety. This candidate addresses the demonstrated restricted-PDF rejection and the missing persistent diagnostics, not every possible upload failure. OCR, whole-manual printing, Edge idle behavior and dependency-security notifications remain separate work.

A process interruption does not automatically resume rendering or re-import a document. Check the library status before retrying to avoid duplicates. The existing 20-page and memory print limits remain unchanged.
