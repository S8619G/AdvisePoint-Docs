# AdvisePoint Docs v1.3.1 verification

September 23, 2026, PDF-controls revision. The integration was tested in disposable Linux libraries and real Linux Chromium/Firefox sessions. The standalone browser-free engine had separately passed user testing on Windows x64 and ARM64. The user subsequently confirmed successful integrated restricted-PDF import on ARM64; broader integrated Windows acceptance and this revised UI still require field testing.

## Verified release

- **Matching application:** both Windows archives contain identical sets of 216 application distribution files. A fresh extraction of the shared source ZIP, clean `npm ci` and `npm run build:nobump` reproduced all 216 files byte-for-byte.
- **Runtime preservation:** Node 20.18.1, native modules and the v1.2.8 updater match the first v1.3.1 binaries, which were previously checked against final v1.3.0. All retained runtime files matched: 1,556 on x64 and 1,554 on ARM64, including updater/runtime notices.
- **Package cleanup:** 125 dependency test/CI assets are omitted from each binary archive. One-off reset, delete-all and prototype cleanup utilities are absent; legal notices and required runtime files remain.
- **Architecture:** every shipped PE executable, DLL and native Node module was checked against its target architecture. The bundled QPDF files match the tested engine manifests and the copies in shared source.
- **Update behavior:** distribution build mode is normal, with standard update controls. Mocked upgrade and rollback tests confirm the unchanged updater carries the newly introduced `pdf-engine` folder and its notices. No real online update or production replacement was executed.
- **Isolated launch:** the optional test launcher selects port 5102 and its own data directory, overrides inherited data settings, reuses recognized test data and refuses linked, unknown or occupied test targets. These launcher checks used a disposable harness, not Windows execution.

## Storage and recovery connections

- **Persistence and hashes:** normal PDFs stay byte-identical; prepared PDFs use the retained bytes for the library file hash and record source hash/size as small metadata, not a second PDF.
- **Recovery:** native PDF page rows and preparation provenance survive deletion/restoration. Older recovery folders can derive missing geometry from their retained PDF.
- **Backup:** exported backups contain the retained PDF and metadata but exclude preparation work folders. Merge restoration into an empty disposable library preserves viewer geometry, provenance and type counts.
- **Print and download:** normal subset preparation and whole-manual handoff remain distinct. Converted files use compatible-PDF labels, and the existing rendered fallback retains its original behavior.
- **Open controls:** whole-document handoff exposes one open action plus Download; the redundant PC-app action was removed. The viewer’s successful Windows-open path no longer raises a browser alert, while errors remain explicit.
- **Failures:** password, no-print, low-quality-only restricted and malformed test inputs did not leave successful imports. Missing engine, mismatched page text, engine warning exit, timeout and cancellation fail closed.
- **Temporary data:** successful and handled failed preparation removed its work folder. Abrupt termination is not claimed to be immediately self-cleaning; old work folders are swept on subsequent preparation.

## Security and remaining acceptance

`npm audit --omit=dev` reported zero vulnerabilities in the production JavaScript dependency graph. This is not a complete vulnerability assessment of bundled native binaries or a PDF security audit.

Type checking still reports 14 pre-existing diagnostics; the normalized diagnostics match the baseline exactly. No clean TypeScript certification is claimed.

Beyond the reported ARM64 restricted-import success, Windows integrated launch/import/restore/upgrade behavior, the revised open controls, Edge use, physical printing and broader PDF coverage remain field-test gates. The previously reported Edge heartbeat/shutdown behavior was not part of this fix and has not been certified resolved. The app viewer has not gained bookmarks or clickable links, even though the retained PDF preserves them in the tested sample.

No existing user library was reset, migrated, converted or upgraded in this workspace. The user authorized publishing this full v1.3.1 release to GitHub for x64 online-upgrade testing and will use local ZIP drag-and-drop for ARM64. Publication status and asset identities are recorded separately after upload.
