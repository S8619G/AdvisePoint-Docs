# AdvisePoint Docs v1.3.0 candidate 13 verification

Date: September 22, 2026. Local-test candidate only. Native Windows acceptance
and physical printing remain pending.

## Root cause and correction

Candidate 12 corrected native subset routing above 50 pages but did not correct
the encrypted-file fallback inside the page-copy worker. That worker refused
encrypted input and the preparation UI treated opening the entire original as
a successful result. This also affected ranges below ten pages. Earlier real
manual checks covered whole-document handoff, while range-content checks used
unrestricted synthetic PDFs. The protected-PDF test accepted the faulty
full-original behavior; that test expectation is now replaced.

Candidate 13 keeps direct copying for unrestricted PDFs. If the selected-page
copy is unavailable because the PDF is encrypted, PDF.js must first confirm
that printing is permitted. The app then creates a temporary selected-page
image PDF at 200 DPI, or 150 DPI for low-quality-only print permission. It
never ignores encryption or changes the stored original. Print prohibition
remains enforced. Whole-native-document jobs over 50 pages still hand off the
original directly; large rendered-PDF original handoff is unchanged.

Preparation uses one canvas at a time, an 8-million-pixel per-page limit,
128 MiB cumulative image/output limits, the existing one-minute warning and
two-minute deadline, cancellation and retry. Done revokes the prepared blob.
These are operation budgets, not a guarantee that browser process memory stays
below 128 MiB. Failed preparation does not silently substitute the full file;
opening the original is an explicit alternative with manual-range guidance.

## Actual manual checks

In both Linux Chromium and Firefox, the library viewer's Range controls select
100–103 from each of the following native manuals:

- 2554ci–7054ci, 2024.7: 793 pages, unrestricted.
- 4004i–7004i, 2025.07: 770 pages, encrypted with printing permitted.
- MZ9500ci series, 2025.09: 791 pages, encrypted with printing permitted.

All six cases produce exactly four pages. Each output page is raster-compared
with its corresponding original page at a common 600-pixel scale. Fractional
PDF dimensions allow a one-pixel raster-size rounding difference; mean absolute
RGBA difference must remain below 12/255. Direct-copy pages compare identically.
The permitted print-image cases pass with differences below 10.2/255.
The primary print button is checked to open the exact verified subset blob.
Original-file SHA-256 hashes remain unchanged after preparation and Done.
All three manuals also pass whole-original handoff and byte-integrity checks.

This verifies the supplied manuals, not every PDF in the user's library.

## Delivery gates

Package checks require ZIP integrity, safe paths, candidate 13/version 1.3.0
markers, x64/ARM64 native PE architecture, identical shared application bundles,
matching source, local-test isolation and byte-identical v1.2.8 runtime modules
and updater. Independent source extraction and rebuild must match the packaged
application distribution. Detailed evidence is saved with the project.

No GitHub publication, update enablement, existing-library reset, reimport or
data deletion is performed. Test fixtures are disposable and separate from
the Windows libraries.
