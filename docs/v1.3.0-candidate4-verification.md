# AdvisePoint Docs v1.3.0 candidate 4 verification

September 20, 2026. Local-test build with matching Windows x64/ARM64 packages and shared source. No publication, updater enabling or existing-library deletion. Candidate 3 printing and candidate 2 fallback/logging are preserved.

## Fix

The previous fallback renderer drew PDF pages and synchronously encoded WebP on the HTTP server thread. Yielding between pages kept health checks alive but severely delayed full-file delivery. Candidate 4 moves PDF parsing/drawing/encoding into a dedicated worker thread.

The serial queue still permits only one rendered document at a time. The worker sends one completed encoded page and waits for acknowledgement; the parent writes that page and its database record, then allows the next page. No SQLite connection or page-file writes exist in the worker. The original 240 DPI, WebP quality 88, PDF resource paths and non-timeout partial-page failure policy are retained.

Parent-owned stage/job deadlines terminate stuck workers. Queue advancement waits for worker termination. Worker crashes, malformed PDFs and commit failures are reported without leaving the queue stuck. Deleted queued jobs are removed; active deletion cancels the worker and ignores late messages, preventing page resurrection. No updater code or runtime dependency versions changed.

## Responsiveness: PASS in the sandbox

Same supplied 724-page fallback manual, while viewing the retained 770-page, 38,160,921-byte manual. One full idle/early/later/post-render run, Linux sandbox Chromium. Progress advanced from 10 to 20 pages and 100 to 110 pages around active samples; observation of the ten-page progress counter is separate from request timings.

| Phase | Search | First visible page | Jump to page 700 | Full original delivery |
|---|---:|---:|---:|---:|
| Idle | 132 ms | 1,092 ms | 842 ms | 496 ms |
| Early rendering | 271 ms | 917 ms | 1,142 ms | 711 ms |
| Later rendering | 268 ms | 1,014 ms | 948 ms | 627 ms |
| After rendering | 252 ms | 764 ms | 856 ms | 519 ms |

Candidate 3's comparable early-render delivery was 37,864 ms and later delivery 12,559 ms. Candidate 4 completes all 724 pages without page errors; all sampled health checks return 200, with a maximum observed response of 13 ms. The earlier worker run also completed all pages with sub-second original delivery, but its progress assertion was too coarse because requests finished before the next ten-page status update. The corrected test explicitly waits for that update separately and passes.

The comparison is not a controlled hardware benchmark or a guarantee of these times on Windows. It measures HTTP delivery, not the external Windows PDF reader's launch. Native x64/ARM64 active-render testing remains pending.
